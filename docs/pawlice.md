## 개요

### 설계 과제

경찰과 도둑은 목표가 다릅니다. 같은 맵 안에서 각자 무엇을 해야 하는지가 명확하면서도, 서로의 행동이 추격과 방해로 이어져야 합니다.

한쪽만 유리하거나 반복 행동만 이어지면 긴장감이 죽습니다. **역할별 목표와 수단을 분리하면서도 서로에게 영향을 주게** 만드는 것이 과제였습니다.

### 나의 활동 — 혼자 만든 멀티플레이를 어떻게 검증했나

1인 프로젝트라 **기획 → 규칙 설계 → UI/UX → 구현 → 테스트** 전 과정을 맡았습니다. 기여도 100%.

문제는 검증이었습니다. **멀티플레이 게임인데 플레이어가 한 명**입니다. 클라이언트를 여러 개 띄워 혼자 두 역할을 번갈아 조작하는 방식으로는 **동시에 벌어지는 상황**을 재현할 수 없었습니다.

그래서 검증 대상을 **‘재미’가 아니라 ‘상태 일관성’**으로 좁혔습니다 — 방 생성·입장, 역할 선택, 게임 시작까지 **세션 상태가 각 클라이언트에 같게 반영되는지**, 그리고 이탈·재입장 시 UI가 이전 상태로 남지 않는지를 반복해서 확인했습니다.

**남은 한계** 밸런스는 검증하지 못했습니다. 경찰과 도둑의 승률이 실제로 비슷한지는 **여러 명이 여러 판을 돌려야** 알 수 있는데 거기까지 가지 못했습니다. 지금 “비대칭이 성립한다”고 말할 수 있는 근거는 설계 논리이지 플레이 데이터가 아닙니다.

### 핵심 성과 · Key Achievements

- **입력 채널 재설계** 추격 중 손은 이미 이동과 아이템 칸에 묶여 있습니다. 남은 채널을 세어 **음성이 유일하게 비어 있음**을 확인하고 STT를 골랐습니다 — 기능이 멋있어서가 아니라 남은 게 그것뿐이었습니다

- **예측 가능한 음성 조작** 자유 발화 대신 **명령 5종을 강아지가 실제로 할 수 있는 행동에 1:1 대응** — 인식 범위는 좁아졌지만 **“말한 대로 안 되는” 경험이 사라졌습니다**

- **비대칭 구조 설계** 승리 조건을 역할별로 나누고 **아이템 자체가 역할의 차이를 만들게** 했습니다. 맵에 랜덤 요소를 넣은 것은 **매 판 같은 경로면 두 번째 판부터 추격이 성립하지 않기** 때문입니다

- **1인 검증 전략** 플레이어가 한 명이라 검증 대상을 ‘재미’가 아니라 **‘상태 일관성’**으로 좁혔습니다 — 방 생성·입장·역할 선택의 동기화, 이탈·재입장 시 UI 잔존 여부

## 기술 의사결정

### Design Decisions

| 결정한 것 | 고른 것 | 기각한 것 | 사유 · 감수한 것 |
|---|---|---|---|
| 동물 조작 입력 | **음성(STT) → 명령 매칭 → 행동** 5종 고정 세트 | ① 키 / 버튼 조작 ② 자유 발화 LLM 대화 | 추격 중 손은 이미 이동과 아이템 칸에 묶여 있습니다. 키를 하나 더 늘리면 조작이 무너집니다. **음성은 손을 쓰지 않는 유일한 입력 채널**이었습니다. 명령을 강아지가 실제로 할 수 있는 행동에 1:1로 대응시켜 “말한 대로 안 되는” 경험을 없앴습니다. *감수*: 인식 범위가 5종에 머뭅니다. |
| 승리 조건 | 경찰 · 도둑 **각각 다른 승리 조건** | 같은 목표로 경쟁 | 비대칭이어야 역할마다 다른 재미가 생깁니다. |
| 아이템 구조 | 도둑은 보물을 담고, 경찰은 상호작용 아이템만 | 양쪽 동일한 아이템 | **아이템 자체가 역할의 차이를 만듭니다.** |
| 맵 · 배치 | 랜덤 탐색 요소 + 동물 상호작용 | 고정 맵 · 고정 배치 | 매 판 같은 경로면 두 번째 판부터 추격이 성립하지 않습니다. |

명령 세트 5종: **이동(따라와) · 탐색(찾아 / 냄새를 맡아) · 견제(짖어) · 제압(도둑을 물어).**

### UX 의사결정 — 손이 이미 묶여 있을 때

Q. 왜 음성(STT)인가 — 버튼 하나 더 만들면 되는데

추격전 중 플레이어의 손은 이미 **이동(WASD)과 아이템 칸(1~4번)**에 묶여 있습니다. 여기에 강아지 명령을 위한 키를 더하면 **조작 자체가 무너집니다.** 손가락이 모자랍니다.

입력 채널을 다시 세어보니 **음성이 유일하게 비어 있는 채널**이었습니다. 기능이 멋있어서가 아니라 남은 게 그것뿐이었습니다.

| 선택지 | 얻는 것 | 치르는 것 | 판정 |
|---|---|---|---|
| 키 / 버튼 추가 | 지연 없음, 구현 간단 | 추격 중 손이 모자람. 조작 난도가 재미를 넘어섬 | 기각 |
| 자유 발화 LLM 대화 | 무엇이든 시킬 수 있음 | **오인식과 응답 지연이 곧 추격 실패.** 실시간 게임에서 몇 초는 치명적 | 기각 |
| **STT + 고정 명령 5종** | 손을 쓰지 않음. 명령이 **강아지가 실제로 할 수 있는 행동에 1:1 대응** | 인식 범위가 5종에 갇힘 | **채택** |

**감수한 것** 표현의 자유도입니다. 대신 **“말한 대로 안 되는” 경험이 없어졌습니다.** 가능한 명령이 좁아도 그 안에서 예측이 정확하면 조작감은 오히려 좋아진다고 봤습니다.

Q. 순서가 반대였던 것 — LLM 응답 지연

처음엔 자유 발화를 목표로 LLM을 붙였습니다. **붙이고 나서야** 실시간 게임에서는 **응답 지연이 곧 조작 지연**이라는 걸 알았습니다. 말하고 강아지가 움직이기까지의 공백이 그대로 게임의 공백이었습니다.

그래서 범위를 5종 고정 명령으로 좁혔습니다. 결과는 나쁘지 않았지만 **과정이 틀렸습니다** — 기능을 먼저 붙이고 범위를 나중에 줄였습니다.

**다음에는** 실시간 기능에 외부 모델을 붙일 때 **기능보다 응답 시간을 먼저 잽니다.** 지연 예산을 먼저 정했다면 처음부터 5종으로 시작했을 것이고, 두 번 만들지 않았을 것입니다.

Q. 비대칭은 어떻게 ‘재미’가 되나

역할을 다르게 만드는 것만으로는 부족합니다. **서로에게 영향을 줘야** 합니다.

그래서 승리 조건을 나누고(경찰/도둑 각각), **아이템 자체가 역할의 차이를 만들게** 했습니다 — 도둑은 보물을 담고, 경찰은 상호작용 아이템만 집습니다. 맵은 랜덤 요소를 넣었습니다. **매 판 같은 경로면 두 번째 판부터 추격이 성립하지 않기 때문**입니다.

**배운 것** 멀티플레이 버그는 전부 **“상태를 누가 갖고 있는가”**에서 나왔습니다. 로비 재입장·이탈 처리가 전부 그 경계 문제였습니다.

## 회고

### Retrospective

잘한 점

명령을 **강아지가 할 수 있는 행동에 1:1 대응**시킨 것.

아쉬운 점

기능을 먼저 붙이고 범위를 나중에 좁혔습니다. **순서가 반대였습니다.**

배운 점

비대칭 설계는 “다르게 만드는 것”이 아니라 **“서로에게 영향을 주게 만드는 것”**이었습니다. 멀티플레이 버그는 전부 **상태를 누가 갖고 있는가**에서 나왔습니다.

다음에는

실시간 기능에 외부 모델을 붙일 때는 **기능보다 응답 시간을 먼저 잽니다.**
